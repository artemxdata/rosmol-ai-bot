# AGENTS.md

## Назначение проекта

`rosmol-ai-bot` — production-oriented AI-бот Росмолодёжи для VK/HDE. Он отвечает по форумам,
мероприятиям, ФГАИС «Молодёжь России» и грантам только на основании опубликованной базы знаний.
Текущий приоритет — закончить и доказать качество решения для Росмолодёжи. Универсализацию под
других клиентов не выполнять без отдельной задачи.

## Активный режим: SECURITY INCIDENT / RECOVERY FREEZE

15 июля 2026 старый сервер был скомпрометирован и выключен. Операторский holdout прерван,
production runtime отсутствует, release status — `NO GO / SECURITY HOLD`.

До нового clean rebuild, перевыпуска секретов и предварительной security/runtime acceptance:

- не включать и не использовать старую VM, её IP, webhook или админку;
- ничего со старого сервера не переносить и не загружать в новый runtime: ни ОС/диски, ни Docker
  images/volumes/cache, ни `.env`, certificates, Redis, PostgreSQL/Qdrant backup, runtime-файлы
  или исполняемые артефакты; допускается только изолированное provider-side forensic preservation
  без использования evidence в рабочем контуре;
- новый контур строить только из чистого vendor image, проверенного Git commit и новых секретов;
  baseline Qdrant индексировать с нуля строго из versioned published seed frozen RC, без свежего
  Yonote Apply;
- перевыпуск всех потенциально раскрытых ключей и секретов вести отдельной обязательной задачей;
- не менять код ответов, routing, prompts, thresholds, KB и dispatcher payload;
- не исправлять по одному замечания Наты или старого cohort: они уже зафиксированы как будущий
  calibration/regression backlog;
- до clean deploy разрешён только отдельно согласованный минимальный infrastructure/security
  patch для нового endpoint/hardening с тестами; он не должен менять behavior/routing/KB;
- старый и новый operator cohort не объединять; новая граница начинается с первого реального
  HDE trace после чистого release handoff.

После предварительной acceptance чистого runtime, но до финального release handoff, отдельно
воспроизвести feedback Наты, получить content verdict по «Машуку» и выполнить один явно
согласованный regression-first correction cycle. Затем пройти полный gate и HDE smoke. Новый
sealed operator cohort начинается только после этих исправлений и финального handoff.

## Архитектурные инварианты

- Backend: FastAPI, асинхронные адаптеры каналов и webhook-и.
- Оркестрация: LangGraph с узлами анализа, retrieval, rerank, generation, verification и response.
- Поиск: Qdrant, `bge-m3`, `bge-reranker-v2-m3`, metadata filters и source-aware rerank.
- Данные: PostgreSQL для trace и долгосрочной памяти, Redis для оперативной сессии и кэша.
- LLM: Cloud.ru, простая модель GigaChat 10B и Max для действительно сложного синтеза.
- Ответ без опубликованных подтверждающих чанков запрещён. Галлюцинации недопустимы.
- Простые уверенные вопросы отвечаются непосредственно из источника без LLM.
- Yonote используется только на чтение. Проект не создаёт, не изменяет и не удаляет документы
  в Yonote.
- Приоритет фактов: опубликованный Yonote -> проверенные XLSX/DOCX-чанки -> уточнение или
  контролируемая эскалация. Ответы операторов являются материалом для gap analysis, а не
  автоматически подтверждённым источником.
- История диалога не ограничивается фиксированным числом ходов. Количество уточнений само по
  себе не является причиной эскалации.

## Поведение бота

- Если не указано мероприятие, а ответ зависит от него, задать уточняющий вопрос.
- Вне тематики, политические провокации и бессодержательная ругань: короткий scope-note без
  оператора.
- Ругательство вместе с понятным вопросом: игнорировать ругань и ответить по существу.
- Прямая просьба об операторе, персональный статус, повторная неустранённая техпроблема или
  отсутствие подтверждённых данных: контролируемая эскалация с точной причиной.
- Суицид, насилие, травля и опасные ситуации: немедленная safety-эскалация без LLM.
- В ответах обращаться к пользователю на «ты» и сохранять tone of voice источника, если это не
  ухудшает ясность.

## Главная метрика

Основная продуктовая метрика — доля тикетов, полностью закрытых ботом без оператора за любое
число сообщений. Дополнительно измеряются first-turn closure, multi-turn resolution, source
coverage, hallucination rate, justified escalation, latency p50/p95, стоимость LLM и cache hit.
Уточнение не считается закрытым тикетом, пока пользователь не получил подтверждённый ответ.

Нельзя выдавать результаты calibration-набора за независимую оценку качества. Наборы должны
быть разделены на calibration и holdout; после исправления кейс остаётся regression-тестом, но
не доказывает обобщающую способность.

## Правила изменений

1. Сначала сформулируй наблюдаемый дефект, ожидаемое поведение и затронутый слой.
2. Перед правкой найди существующий код и тесты; не добавляй параллельную реализацию.
3. Делай минимальное изменение. Не переписывай архитектуру и KB ради одного примера.
4. Для каждого исправления добавляй regression-тест.
5. Не запускай большие eval-наборы повторно без понятной гипотезы и критерия успеха.
6. Не меняй одновременно KB, routing, пороги и prompts без необходимости: иначе невозможно
   определить причину изменения качества.
7. Перед изменением production-конфигов, миграцией, полной индексацией или rollback явно
   предупреди пользователя.
8. Не отменяй чужие изменения и не используй destructive Git-команды.
9. После значимого этапа обнови `docs/CURRENT_STATE.md`.

## Данные и секреты

- Никогда не выводи и не коммить `.env`, токены, пароли, SSH-ключи, API keys и DSN.
- Сырые HDE-тикеты и производные приватные данные хранятся только в `data/private/`, не входят
  в Git, Docker image и серверные артефакты.
- В Git допустимы только обезличенные, вручную проверенные eval-кейсы и агрегированные отчёты.
- Не индексируй операторские ответы автоматически как факты.

## Проверки

Минимум перед commit:

```powershell
.venv\Scripts\ruff.exe check .
.venv\Scripts\python.exe -m pytest
.venv\Scripts\python.exe scripts\index_kb.py --validate-only
```

Массовые проверки выполняются через локальный/server-local `/ask`, а не через HDE/VK.
HDE имеет общий лимит 300 RPM и бан на 20 минут; бот оставляет запас и не используется как
нагрузочный транспорт.

Перед релизом используй `docs/pre_pilot_release_checklist.md`. Релиз считается готовым только
после server-local quality suite и короткого ручного HDE/VK smoke.

## Git и deployment

- Основная ветка: `master`.
- GitHub: `artemxdata/rosmol-ai-bot`.
- Старый сервер выведен из эксплуатации. Новый сервер пользователь разворачивает вручную только
  после согласованного clean-rebuild и secret-rotation плана; Codex готовит commit, push и точные
  безопасные команды.
- Не предполагай, что push автоматически применился на сервере.
- После deployment сверяй commit, `/ready`, Qdrant count, trace и результат smoke.
- Прежний публичный адрес админки относился к скомпрометированному хосту и выведен из
  эксплуатации; не открывать его и не использовать TLS/admin credentials старого
  контура. Новый постоянный HTTPS URL фиксируется только после clean rebuild. Не выводить admin
  token в команды, логи или документы.

## Handoff

Перед завершением длинной задачи или переходом в новый чат обнови `docs/CURRENT_STATE.md`:

- дата и commit;
- что сделано и проверено;
- что выполняется сейчас;
- точный следующий шаг;
- результаты тестов;
- риски и запреты.

Для recovery handoff зафиксируй статус Selectel ticket, факт `SHUTOFF`, прогресс ротации
секретов, новый trusted commit/host, результаты нового security/release gate и новую cohort
boundary. Прерванный cohort не выдавать за финальную конверсию.

Новый чат должен сначала пересказать состояние проекта по этим файлам и только затем менять код.
