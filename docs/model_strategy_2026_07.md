# Аудит архитектуры и качества, июль 2026

## Вывод

Текущую основу менять не нужно. FastAPI + LangGraph + hybrid RAG + reranker +
детерминированный verifier — подходящая production-архитектура для бота
Росмолодёжи. Главная гарантия остаётся прежней: модель формулирует ответ только
по опубликованным источникам, а не заменяет поиск знаний собственными знаниями.

GPT-5.6 Sol используется только как инструмент разработки: для более глубокого
анализа кода, метрик и слабых мест. В runtime `rosmol-ai-bot` она не добавляется.
Production-каскад остаётся прежним: GigaChat 10B для простых задач и GigaChat
Max для сложных. Нового API-провайдера и новых переменных окружения нет.

Официальные источники:

- https://openai.com/index/previewing-gpt-5-6-sol/
- https://help.openai.com/en/articles/20001325-a-preview-of-gpt-56-sol-terra-and-luna

## Текущий каскад

1. Детерминированные правила обрабатывают safety, PII, прямой запрос оператора,
   персональные действия и очевидный off-topic.
2. Query Analyzer выделяет форум, тему, параметры и составные вопросы.
3. Qdrant выполняет hybrid retrieval по bge-m3 и метаданным.
4. bge-reranker-v2-m3 ранжирует кандидатов.
5. Уверенный типовой запрос получает исходный опубликованный chunk без LLM.
6. Составной запрос синтезируется 10B или Max только по выбранным источникам.
7. Verifier проверяет scope, покрытие аспектов и source IDs. Неподтверждённый
   ответ не отправляется пользователю.

Это граф состояний с независимыми проверками, а не свободная мультиагентная
система. Для текущего продукта это преимущество: поведение воспроизводимо,
дешевле и проще аудируется.

## Измеренный baseline

Июньский live eval на 509 обезличенных кейсах:

| Метрика | Все | Типовые | Нетиповые |
|---|---:|---:|---:|
| Автоответ | 58,5% | 61,3% | 54,5% |
| Без немедленного оператора | 75,8% | 81,7% | 67,5% |
| Передача оператору | 24,2% | 18,3% | 32,5% |

Генеративная LLM использовалась только в 4 из 509 кейсов. Значит, основные
потери baseline связаны не с мощностью генератора:

- `low_confidence`: 40;
- `insufficient_sources`: 28;
- `personal_status`: 24;
- `technical_issue`: 9;
- `analyzer_failed`: 8.

Дополнительно в eval-выборке обнаружены старые ответы бота, служебные реплики,
рассылки и коммерческие предложения. До сравнения моделей набор должен быть
повторно очищен, иначе метрика одновременно занижает и завышает качество.

## Исправления по итогам аудита

- Неизвестный запрос при недоступности анализатора теперь получает безопасное
  уточнение, а не автоматическую передачу оператору.
- Общие правила посещения с ребёнком или супругом не считаются персональной
  операцией с билетом. Персональные переоформления и восстановление остаются у
  оператора.
- Eval-фильтр исключает старые ответы поддержки, рекламные и служебные тексты.
- LLM-клиент переиспользует HTTP connection pool между запросами.

## Роль GPT-5.6 Sol в этой работе

- глубокий офлайн-аудит архитектуры и ошибок;
- поиск KB gaps и группировка неразрешённых тикетов.
- проверка связности правил analyzer/retrieval/generator/verifier;
- разработка и ревью точечных исправлений;
- анализ результатов текущего каскада 10B/Max.

Интеграция Sol в продукт не является частью этого аудита и не планируется.

## Условия повторного quality-теста

Сравнивать старую и исправленную версии бота нужно на одном очищенном
frozen-наборе. Основные метрики:

- hallucination rate: 0%;
- source coverage: не ниже текущего уровня;
- автоответ и корректное уточнение;
- доля ложных передач оператору;
- p50/p95 latency;
- стоимость одного успешно закрытого обращения.

Изменение считается полезным только если оно повышает долю корректных
автоответов или уточнений без ухудшения source coverage, safety и p95 latency.
