# Политика ответов по операторским сценариям

Документ фиксирует правила, извлечённые из обезличенных диалогов HDE и внутренних инструкций Yonote. Операторские ответы используются для калибровки поведения и тестов, но не публикуются в RAG как автоматически подтверждённые факты.

## Приоритет источников

1. Единственный factual authority — опубликованные записи `source_type=yonote` из
   проверенного versioned release snapshot.
2. Если подтверждённого Yonote-факта нет, бот задаёт одно конкретное уточнение или передаёт
   обращение по контролируемому правилу.
3. Legacy XLSX/DOCX используются только как migration/regression baseline и не могут
   подтверждать пользовательский ответ.
4. Операторские пары вопрос-ответ дают сценарий, согласованную сервисную формулировку и кандидат
   на пробел в базе, но не являются фактическим источником.

Live Yonote используется только на чтение для управляемого content/release цикла. Runtime
отвечает по проверенному snapshot и не подмешивает изменения live API напрямую.

Операторы дополнительно используют сайт ФГАИС, официальные соцсети, ответы второй
линии и внутренний новостной чат. Пока эти источники не подключены к боту как
версионируемые read-only источники, расхождение с отдельным операторским ответом
не доказывает ошибку RAG. Такой кейс попадает в список пробелов источников на
ручную проверку, а факт из ответа оператора не индексируется автоматически.

## Согласованный NLU-copy contract

Старый NLU задаёт согласованные сервисные реплики и структуру, но не актуальные факты. Exact copy
хранится в `data/response_contract_v1.json`; raw legacy `config.json` не входит в репозиторий.

| Сценарий | Точная реплика |
|---|---|
| Чистое приветствие, `/start`, `Начать` | `Чем я могу быть полезен?` |
| Перевод на оператора | `Перевожу на оператора. Пожалуйста, ожидай.` |
| Благодарность | `Всегда рад!` или `Рад быть полезным!`; выбор детерминирован |
| Завершение | `Обращайся! 😊` |
| Не назван форум | `Уточни, пожалуйста, название форума, о котором спрашиваешь.` |
| Не названо мероприятие для вопроса о датах | `Подскажи, пожалуйста, даты какого мероприятия тебя интересуют?` |
| Непонятный запрос | `Я не совсем понял вопрос. Попробуй переформулировать — я помогу с мероприятиями, грантами и техническими вопросами.` |

Уточнение с вариантами начинается с `Пожалуйста, уточни свой вопрос 👇`, затем содержит реальные
нумерованные варианты. Placeholder `{buttons}` запрещён. Чистое приветствие получает fixed
response; приветствие вместе с содержательным вопросом не скрывает вопрос.

Согласованное описание возможностей:

> ЗаБотливый Бот создан, чтобы информировать о деятельности Росмолодёжи, форумах, грантах и
> возможностях для молодёжи.
>
> Спрашивай о мероприятиях, проектах и поддержке — я найду ответ!

Текущие safety, profanity-routing и controlled escalation имеют приоритет при конфликте со
старым сценарием. Причина эскалации фиксируется в trace и не выводится пользователю техническим
текстом.

## Структура динамического ответа

- Порядок: прямой ответ, только необходимые детали, одна ссылка или следующий шаг.
- Простой ответ — не более 450 символов, составной — не более 900.
- Механическое обрезание запрещено.
- Короткий релевантный Yonote-фрагмент допустим без LLM.
- Длинный, многотемный или multi-source материал проходит grounded synthesis.
- При сбое LLM полный исходный chunk пользователю не возвращается: после безопасной попытки
  формирования выполняется уточнение или controlled escalation.
- LLM не добавляет эмодзи. Эмодзи разрешены только в catalog-owned сервисных репликах.
- Внутренний `response_profile` выбирается из `dates`, `application`, `eligibility`, `documents`,
  `selection_status`, `program`, `travel`, `accommodation`, `food`, `accessibility`, `grants`,
  `technical`, `generic`; внешний payload остаётся обычным `response_text`.
- Миграционная матрица однозначно относит каждый из 762 достижимых legacy-узлов к одной
  disposition-категории и одному из этих 13 профилей; raw legacy-тексты и факты в матрицу не
  входят.

## Матрица поведения

| Ситуация | Поведение |
|---|---|
| Вопрос полностью покрыт источниками | Ответить самостоятельно, сохранить факты и ссылки источника |
| Не указано мероприятие, а условия от него зависят | Уточнить название мероприятия без передачи оператору |
| Вопрос вне тематики, провокация или ругань без полезного запроса | Коротко обозначить тематику бота без передачи оператору |
| Ругательство сопровождает понятный вопрос по базе | Игнорировать ругательство и ответить по существу |
| Первая техническая проблема | Дать безопасные шаги первой линии из Yonote |
| Безопасные шаги уже не помогли | Передать специалисту с причиной `repeated_support_failure` |
| Пользователь просит проверить конкретную заявку, письмо или персональный статус | Передать специалисту с причиной `personal_status` |
| Пользователь прямо просит оператора | Передать с причиной `operator_requested` |
| Угроза жизни, насилие, травля или психологический кризис | Немедленная safety-эскалация без LLM |

## Диалог и уточнения

- Полная маскированная история диалога хранится в PostgreSQL. В Redis находятся последние 20 пар `user/bot`, выбранное мероприятие, темы, извлечённые сущности и ожидаемое уточнение.
- Вытесненная из оперативного окна часть диалога сохраняется как компактное резюме; после истечения Redis-сессии последние сообщения и структурированный контекст восстанавливаются из PostgreSQL.
- Если мероприятие уже названо, последующие вопросы про билет, проезд, питание, проживание, программу, документы и участие относятся к нему, пока пользователь явно не назовёт другое событие.
- Если условия зависят от мероприятия, но его название неизвестно, бот не выбирает похожий форум из поиска, а просит уточнить название.
- Короткий ответ пользователя на уточнение объединяется с исходным вопросом. Заданные вопросы сохраняются в структурированной памяти, чтобы не терять цель диалога.
- Короткие продолжения вроде «А куда именно?» восстанавливают предыдущую категорию и вопрос. Самостоятельный новый вопрос про гранты, ФГАИС или техподдержку не склеивается со старым форумным контекстом.
- Количество уточнений само по себе не является причиной передачи оператору. Диалог продолжается, пока пользователь не получит подтверждённый ответ, явно не попросит оператора или не сработает отдельное правило безопасности/персонального статуса.
- Явно названное новое мероприятие всегда заменяет старый контекст; явный переход в другую категорию очищает старое мероприятие. Кэш для контекстных продолжений и ответов на уточнение не используется.

## Безопасность

- Бот не просит присылать логин, пароль, СНИЛС, серию или номер паспорта.
- Для диагностики допустим снимок экрана только без персональных данных.
- Паспорт можно упоминать как документ, который требуется взять на мероприятие, если это прямо указано в официальном источнике.
- Сырые операторские диалоги и персональные данные не входят в Git и публичные отчёты.

## Контроль качества

- `calibration` используется для разработки и исправления маршрутизации.
- `holdout` не используется для подгонки и запускается после завершения калибровки.
- Главная конверсия считается как доля полных тикетов, полностью закрытых ботом без оператора за
  любое число сообщений.
- First-turn closure измеряется отдельно и не подменяет главную ticket-level конверсию.
- Уточнение не считается закрытием само по себе. Multi-turn resolution фиксируется только если
  после уточнения пользователь получил подтверждённый ответ без оператора.
- Таймаут инфраструктуры считается техническим сбоем, а не ошибкой знания.
